# 入库实战区 · 安卓手机版

电脑版「入库实战区管理系统」的手机版。界面、筛选方式、统计栏和电脑版完全一样，  
数据就是电脑上那个 `shizhanqu.db`（8 万多条），拷到手机就能查。

- **零第三方依赖**：只用系统自带的 WebView 和 SQLite，打包出来的 APK 只有 2MB 左右
- 查询逻辑全部写在 `app/src/main/assets/web/jsdb.js` 里（和电脑版 db.py 逐条对照验证过），  
  以后想改查询逻辑，直接改这个文件即可，**不用重新编译 APK**
- 支持：常用筛选（动态列表）/ 全部字段筛选 / 筛选结果统计 / 写记录复盘 / **导入 Excel** / 导出 CSV / 新增删除
- 支持横屏：横过来会自动压扁顶栏和工具栏，把高度全留给数据表
- **新版 APK 可以直接覆盖安装**：云端编译用固定签名钥匙，装新版不用卸载旧的，数据库和复盘记录都在
- 不支持：数据包同步（电脑上更新数据仍靠传新的 db 文件）

## 一、怎么编译出 APK

### 方式 A：GitHub Actions 云端编译（推荐，本机什么都不用装）

1. 注册 / 登录 GitHub，新建一个仓库（比如 `shizhanqu-android`）
2. 把本文件夹里的全部文件传上去（网页上拖拽上传也行，`实战区管理系统_安卓` 文件夹里的内容要传到仓库根目录）
3. 传完后 GitHub 会自动开始编译（仓库页的 Actions 标签能看到进度，约 3~5 分钟）
4. 编译完成后进这次运行页面，在底部 Artifacts 下载 **入库实战区APK**
5. 把 APK 传到手机安装（需允许「安装未知来源应用」）

> 以后数据更新了不需要重新编译；只有改了 App 本身才需要重新传一次代码。
> 云端编译出来的 APK **用的是固定签名钥匙**（首次编译时生成，之后一直复用），
> 所以新版本可以**直接覆盖安装，不用先卸载旧的**，手机里的数据库和复盘记录都会保留。
> ⚠ 只有这一次例外：手上装的是老版本（随机调试签名），**需要先卸载一次**再装这个；
> 从这一个版本往后，都是直接覆盖就行。

### 方式 B：自己装 Android Studio 编译

1. 装 Android Studio（会自动下载 SDK，需要几个 GB 空间）
2. 打开本文件夹（Open 项目根目录）
3. 菜单 Build → Build App Bundle(s) / APK(s) → Build APK(s)
4. 产物在 `app/build/outputs/apk/debug/`

要求：JDK 17、compileSdk 34（项目已配置好，直接点就行）。

> 本机编译用的是 Android Studio 自己的调试钥匙（每台机器固定一把），
> 同一台机器编出来的版本互相也能直接覆盖安装，数据一样不会丢。

### 发新版本时记得改一个数字

`app/build.gradle` 里的 `versionCode`（现在是 2）。每次出新版往上加 1，
版本号比手机上装的旧，安卓同样会拒绝安装。

```gradle
defaultConfig {
    versionCode 2      // 每次发新版本记得往上加
    versionName "1.1"
}
```

## 二、第一次把数据装进手机

1. 电脑上：顶栏点 **「数据同步」→「导出手机版数据库」**，  
   会生成 `导出\手机版_shizhanqu_日期.db`（导出前会自动把未落盘的数据写进文件，请先关闭电脑版程序再导，避免文件被占用）
2. 把这个 `.db` 文件传到手机（微信「文件传输助手」/ QQ / 数据线都行），文件会落在手机「下载」目录
3. 手机上打开 App → 点 **「数据」→「选择数据库文件」**，在文件选择器里找到刚传的 `shizhanqu.db`
4. 加载完成后自动回到主界面，就能查了

## 三、以后怎么更新数据

两条路，看手头有什么：

### 3.1 手头只有 Excel 表格（在外面时最常用）

1. 把 `.xlsx` 传到手机（微信「文件传输助手」/ QQ / 邮件都行）
2. App 里点 **「导入」→ 选导入方式 → 「选择 Excel 文件」**，在系统文件选择器里找到它
3. 等进度条走完，会告诉你：新增几条、覆盖几条、没变化几条

- **按新ID更新（推荐）**：系统里没有的新ID → 新增；内容有变化 → 覆盖；没变化 → 原样不动  
  默认勾了「保留已有的记录 / 复盘」，表格里这两列是空的也不会清掉你在手机上写的
- 8 万行大约 1~3 分钟（解析表格慢一点，属正常），中途别退出 App
- 判定规则和电脑版 `db.py` 的「按新ID更新」**逐行对照验证过**：同一份表重复导入，结果是 0 新增 0 覆盖 84027 条未变化

### 3.2 手头有电脑上导出的 db 文件

1. 电脑上照第一节第 1 步导出新的 `.db`
2. 传到手机覆盖（同名文件会存在「下载」里）
3. App 里点 **「数据」→「重新读取」** —— 之前选过的文件已被记住，不用再找一遍

## 三点五、置顶 + 快捷检索（手机上对比比赛用）

### 置顶

点开任意一条比赛，它就自动被设为**置顶参照行**。以后不管你怎么改筛选条件，
它都排在窗口**第一行**，方便拿它跟筛出来的比赛逐项对照。

- 它本来就在结果里 → 直接挪到最前面（左侧一条橙色竖杠，命中数不变）
- 它被当前条件筛掉了 → 只在第 1 页把它补到最前面，格子前面带一个「置顶」小标，
  表示"这条其实不符合当前条件，只是摆这儿给你对照"
- 顶部标签栏会多一个橙色的「置顶」标签，点 × 取消
- 详情面板里的「置顶 / 取消置顶」按钮也能切换；关掉 App 再打开还记得

### 快捷检索

点开一条比赛后，按详情面板里的 **「以此检索」**，会以它为中心自动设好 4 个条件：

| 字段            | 规则                  |
| ------------- | ------------------- |
| 胜负（wl）       | **固定值**：精确等于本条的值    |
| 负胜（lw）       | **固定值**：精确等于本条的值    |
| 初让胜（s_h_win） | 本条的值 **± 0.02** 的范围 |
| 初让负（s_h_lose） | 本条的值 **± 0.02** 的范围 |

浮动范围可以用旁边的 **±0.02** 按钮切换：0.01 / 0.02 / 0.03 / 0.05，会记住你的选择。

**这 4 个条件就是普通筛选条件**，所以检完之后你可以：

- 继续叠加别的条件（半场、联赛、让球、时间段……随便加）
- 在顶部标签栏单独 × 掉其中任何一个
- 在左侧「全部字段」面板里直接改那两个范围的上下限（已经帮你填好了）

本条本身一定在结果里，而且因为置顶，它就排在第一格，跟下面筛出来的正好做对比。

## 四、手机上写的记录 / 复盘怎么回到电脑

手机上的修改保存在手机内部的那份数据库里，**不会自动传回电脑**。回传办法：

1. 手机 App：点 **「导出」→「全部数据」**，生成 CSV 保存（里面包含你在手机上写的记录 / 复盘）
2. 把 CSV 传回电脑
3. 电脑版：**「导入数据」→ 选这个 CSV → 导入方式选「按新ID更新」**  
   → 手机上写的内容就会合回电脑数据库（电脑上已有的、手机上没改的行不会被动）

反过来，电脑上写了复盘想让手机看到：重新导出 db → 传手机 → 「重新读取」。  
注意：重新读取会用电脑的 db **整体替换**手机里那份，手机上还没回传的记录会丢，  
所以先做完第四节的回传，再做第三节的更新。

## 五、手机版与电脑版的差异

|                 | 电脑版         | 手机版              |
| --------------- | ----------- | ---------------- |
| 打开记录            | 双击表格行       | **点一下**表格行       |
| 筛选面板            | 左侧常驻        | 点顶栏「筛选」滑出        |
| 导入 Excel        | 有（xlsx/csv）  | 有（xlsx，判定规则一致）   |
| 置顶参照行           | 无           | 有（选中即置顶，筛选后仍在首行） |
| 快捷检索            | 无           | 有（胜负/负胜固定值 + 初让±0.02） |
| 数据同步            | 有           | 无（靠传 db 文件）      |
| 导出              | xlsx / csv  | csv（存到你选的位置）     |
| 横屏              | 有           | 有（自动压缩横条）        |
| 数据库位置           | 程序目录 data\\ | App 内部（从你选的文件复制） |

## 六、工程结构

```
app/src/main/
├── java/com/shizhanqu/app/
│   ├── MainActivity.java     WebView 壳 + 系统文件选择 / 保存
│   ├── DbBridge.java         网页 ↔ SQLite 桥（执行 SQL / 复制 db / 保存文件 / 导入）
│   └── XlsxToCsv.java        xlsx → CSV（只用系统自带的 Zip + XmlPullParser，零依赖）
├── assets/web/
│   ├── index.html            界面（与电脑版同源）
│   ├── style.css             手机端样式追加在文件末尾的 @media 区块
│   ├── app.js                界面逻辑（与电脑版同源，MOBILE 分支做了手机适配）
│   ├── jsdb.js               数据层：db.py 的 JS 版（拼 SQL）
│   └── mbapi.js              api() 到 JSDB / 安卓桥的适配层
└── AndroidManifest.xml
```

想改查询逻辑 / 加字段：改 `jsdb.js`；想改界面：改 `app.js` / `style.css` / `index.html`。  
改完 assets 里的网页后，重新编译一次 APK 即可（或者不重编，调试时可用 Chrome 远程调试验证逻辑）。
